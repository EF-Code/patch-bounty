# Continue PatchBounty

This repository contains the local prototype and a verified NEAR testnet demonstration. Start with [README.md](README.md), [the implementation roadmap](docs/ROADMAP.md), and [the testnet evidence](demo/testnet-20261105/README.md). The fixture verifier, escrow, deterministic generator, settlement preparation, and static evidence review are implemented. A live testnet payout, rejection and replay checks, transfer failure/retry, and expiration refund have been observed and recorded. The deployed contract is unaudited and upgradeable; the escrow design documents its limitations.

The user says they claimed the **NEAR AI Cloud $10 credits** through NEAR Builders and added the resulting API key to their environment vault. Do not ask them to post the key in chat or commit it. On 2026-11-07, the environment reported `NEAR_AI_API_KEY` ready and a live request succeeded. The user is on mobile and cannot use a terminal. If the credential is unavailable in a future environment, use secure settings or a credential workflow, rather than asking for the key in chat.

The first live `generate.py --near-ai` run produced a qualifying synthetic candidate, which was independently checked by `verifier.py`; see [the saved run](demo/near-ai-20261107/README.md). The integration does not verify gateway/model attestations or response signatures. Continue with the unchecked roadmap items, including defining and implementing the privacy and attestation checks before claiming private inference was verified. Only the deterministic verifier may determine eligibility; model output cannot authorize payment.

The user authorized spending **testnet** NEAR for the demo. Do not deploy to mainnet or purchase credits or spend the user's funds without authorization. Preserve the fixed fixture allowlist and sandbox; never run arbitrary submitted code on the host. See [AGENTS.md](AGENTS.md) for the project constraints.

The most recent local verification passed 16 Python tests, 10 Rust unit tests, and a local NEAR sandbox integration test. The sandbox test needed a local file-descriptor workaround in the previous environment. See [the testnet walkthrough](docs/TESTNET.md) for build and execution commands. Testnet account keys and locally installed tools are outside this repository and may not persist into a different environment; no private keys or API credentials belong in Git.
