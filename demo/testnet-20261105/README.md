# Testnet demonstration: 2026-11-05 UTC

This is a real NEAR **testnet** deployment and settlement using faucet-funded testnet NEAR. It is not a mainnet deployment or a production security assessment. The deployed contract account is `escrow.pb-1793920854-24723.testnet`; its on-chain Wasm SHA-256 matched the local build, `754ea3374fb426381300768cb92d691853fc48ba92b1ad328daf14d21e6cdcd1`, at finalized block 276408419. The account retains a full-access key and could be redeployed, so independently check its code and permissions before relying on its current behavior. The initial [deployment transaction](https://explorer.testnet.near.org/transactions/EruZATrtePn1A5Pj35p3fLh7qrKX9uuRf4SeimnnqmZD) and the public transaction records below identify the observed deployment, not an immutable deployment guarantee.

Challenge `0` was funded with 0.1 testnet NEAR: a 0.08 NEAR reward and 0.02 NEAR retained as storage allowance. The claimant submitted a benign candidate, which the authorized verifier rejected, and then submitted the qualifying candidate. An unauthorized approval failed. The verifier approved claim `1`; the [approval transaction](https://explorer.testnet.near.org/transactions/4Dhy6DQwyDUTrtCBHqe2mCsBon3nN1oueoZdomfW5HPk) includes a successful transfer and callback. The recorded finalized account balances show that the claimant's balance increased by exactly 0.08 NEAR, and the finalized challenge state is `paid`. A [repeat approval](https://explorer.testnet.near.org/transactions/FM33aFD2hYX1pmGZmYBX4JnTFNtoQKYXmYdNKCHcj9G4) failed.

Challenge `1` tested cross-challenge replay and expiration. Reusing challenge `0`'s evidence digest was [rejected](https://explorer.testnet.near.org/transactions/Bvp1JecDteWSHTuABWCJVQhRvbLwaTEVr1RbWsTYoYJd). After the challenge expired, the creator [refunded](https://explorer.testnet.near.org/transactions/4Huf7iCL3KwJX8trkpwhd6Sf6jJ6YPWnoir5qwRm3ZmF) its 0.01 NEAR reward; the final state is `refunded`.

Challenge `2` tested transfer recovery with a 0.001 NEAR reward. A test claimant submitted a qualifying claim, then its account was deleted before approval. The [approval transaction](https://explorer.testnet.near.org/transactions/NySNZXu1UR3CnLxtnziukAdiCaq8ERtqiBr7P6cY4kz) produced a failed transfer and a successful callback, leaving the challenge in `approved` state. After recreating the same test account, a [retry](https://explorer.testnet.near.org/transactions/CQbGu8NKrrXx1EvUpYrY91GdJfgTo8oMqvnZLCqghRtB) succeeded and the final state is `paid`.

`transactions.json` contains finalized public RPC results for the deployment and all demo transactions. `qualifying-evidence.json` binds the verifier result to the finalized claim, and `review.html` renders that evidence as a static snapshot; the snapshot predates payout. `balance-before.json`, `balance-after.json`, `final-challenge.json`, `transfer-failure-state.json`, and `additional-final-challenges.json` preserve the observed states. These are unsigned local records, not independent execution attestations. The NEAR AI Cloud integration was not used for this demonstration because no API key was configured; the candidate came from the deterministic generator.

Dedicated account credentials were created outside the repository under the execution user's `~/.near-credentials/testnet/` with restricted file permissions. Those files contain private keys and must not be committed or shared. See [the walkthrough](../../docs/TESTNET.md) to reproduce the workflow with your own accounts and [the escrow design](../../docs/ESCROW.md) for known limitations.

On 2026-11-07, a fresh finalized testnet RPC query at block 276654751 returned challenge `0` as `paid` with the same 0.08 NEAR reward and returned deployed Wasm SHA-256 `754ea3374fb426381300768cb92d691853fc48ba92b1ad328daf14d21e6cdcd1`. This is a point-in-time RPC observation, not a light-client proof; the full-access key still permits later changes.
